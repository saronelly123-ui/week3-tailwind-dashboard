# Mintly Admin Dashboard — Week 3 Tailwind CSS

**Live site:** _Deploy this repository and paste the public URL here._

A responsive admin dashboard for a fictional online store, built with plain HTML, a small amount of JavaScript, and Tailwind CSS v4 through the official CLI (not the Play CDN).

## Features

- Responsive sidebar navigation with a mobile menu toggle.
- Four KPI cards, a six-row orders table, revenue chart, activity feed, top products, and an invitation form.
- Mobile-first layouts for small phones, tablets, laptops, and wide desktops.
- Order status filtering, table search, CSV export, invitation form validation, and a working mobile navigation toggle (bonus).
- Reusable component classes declared with `@apply` in `src/input.css`.

## Run locally

1. Install Node.js (LTS) if it is not already installed.
2. Open this folder in VS Code.
3. In the terminal, run:

   ```bash
   npm install
   npm run build
   ```

4. Open `index.html` with VS Code Live Server. Whenever you edit Tailwind classes, run `npm run build` again. To keep the generated CSS updating while you work, run `npm run dev` in a separate terminal, then open `index.html` with Live Server.

> `src/output.css` is generated by the Tailwind CLI. Commit it if you want GitHub Pages to serve the site directly without a build workflow.

## How I customized Tailwind

I customized Tailwind CSS v4 to give Mintly a consistent visual identity instead of relying only on the default utility palette. In `src/input.css`, the `@theme` block defines a custom `brand` color scale from pale mint to deep green. The green palette is used for the primary action buttons, active navigation, progress indicators, and positive accents. I also set the default font family to Inter, which gives the dashboard a clean, readable appearance across mobile and desktop screens.

I created reusable classes inside `@layer components` with `@apply`. The `.card` class provides a shared border, white background, rounded corners, and subtle shadow. `.btn-primary` and `.btn-secondary` keep button spacing, typography, focus outlines, and hover transitions consistent. `.badge` standardizes compact status labels, while `.nav-link` and `.field` keep navigation items and form controls visually consistent. This reduces repeated utility strings and makes later design changes easier. Most styling still uses Tailwind utilities directly in the HTML, with responsive prefixes such as `sm:`, `md:`, `lg:`, and `xl:` to follow a mobile-first approach.

## Responsive checks

Test these viewport widths in browser DevTools: **375px**, **768px**, **1024px**, and **1440px**. The table intentionally uses `overflow-x-auto` and a minimum width so it scrolls horizontally on narrow screens instead of stretching the page.

## Deployment (GitHub Pages)

1. Run `npm install` and `npm run build` so `src/output.css` exists.
2. Push the repository to GitHub.
3. Open **Settings → Pages** in the repository.
4. Under **Build and deployment**, choose **Deploy from a branch**, select `main` and `/ (root)`, then save.
5. When GitHub provides the published URL, paste it at the top of this README.

## Suggested Git workflow (10 meaningful commits)

Use a feature branch for each focused change, open a Pull Request on GitHub, and merge after reviewing the diff. Suggested commit-sized milestones:

1. `chore: initialize Tailwind CLI project`
2. `feat: define Mintly brand theme and component classes`
3. `feat: build responsive dashboard shell and sidebar`
4. `feat: add top bar and profile controls`
5. `feat: add responsive KPI cards`
6. `feat: build orders table with status badges`
7. `feat: add revenue chart and activity panel`
8. `feat: add top products and invite form`
9. `feat: add search filters and CSV export`
10. `docs: add setup, customization, and deployment guide`

For the assignment, create branches such as `feature/dashboard-shell`, `feature/orders-table`, and `feature/activity-panels`; push each branch, open a PR, and merge it after checking the changes. These are suggested milestones; this starter folder does not claim that commits, PRs, deployment, or screenshots have already been created.
